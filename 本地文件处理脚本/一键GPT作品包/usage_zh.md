# 一键作品包使用说明

这个工具用于把“一篇笔记”的 GPT 文案和图片整理成一个作品包。

## 放在哪里

建议把工具安装到固定程序目录，例如 `D:\AICode\运行数据\chatgpt-work-package`。图片下载目录可以是 `D:\Download`，成品库可以放在项目目录；三者不必在一起。

文件夹里会有：

- `一键生成作品包.vbs`：平时只需要双击这个。
- `make_work_package.ps1`：后台执行脚本，通常会隐藏。
- `workpkg_config.json`：配置文件，可以改成品库名字和提示语。
- `设置作品包目录.vbs`：需要更换保存位置时，双击后可直接粘贴完整地址，也可浏览选择文件夹。

## 怎么用

1. 先把这一篇笔记的图片下载到设置中的“图片下载目录”。
2. 再复制 GPT 生成好的文案。
3. 双击 `一键生成作品包.vbs`。
4. 工具会在成品库里生成一个新作品包。
5. 如果成品库一级散着的笔记帖子凑满 14 个，工具会自动整理进下一个正常显示的 `作品集_001 / 作品集_002 ...`。

## 生成结果

如果没有单独配置成品库路径，默认会生成：

```text
成品库\日期时间_文案第一行
```

作品包里面会有：

- `文案_日期时间.txt`
- `GPT会话溯源.json`：按顺序记录 ChatGPT 账号名和本次对话链接。
- `标题_日期时间_01.jpg / 标题_日期时间_02.png / 标题_日期时间_03.webp ...`

溯源信息由 ChatGPT 辅助油猴脚本在打包时附加，不会混进文案正文；链接和账号名只写入本地作品包。旧页面或未启用辅助脚本时，仍可正常打包，只是不生成溯源文件。

不会再创建空白分隔图。作品包里只放文案和你下载的作品图。

图片会按修改时间排序后再重命名，文件名带文案第一行标题和日期时间。工具也会给图片设置连续时间，尽量让手机按名称排序、按时间排序都更好分辨。

只处理设置的图片下载目录最外层。新版网页脚本会为同一图片组写入统一批次 ID、序号和总数，本地端只处理最新且完整的一批；不会进入子文件夹。

## 作品集自动整理

默认规则：

- 只看成品库这一层的作品包文件夹。
- 每篇笔记帖子文件夹现在使用正常可见名称，例如 `20260720_123456_标题`，不再自动添加点号。旧版已经生成的 `.20260715_标题` 仍会被兼容识别，无需手动修改。
- `作品集_001`、`作品集_002` 这种外层整理文件夹正常显示；旧版带点号的作品集也会兼容识别并跳过。
- 每 14 个作品包自动收进一个新作品集。
- 每生成一个新作品集，会顺带生成同名 ZIP 压缩包，比如 `作品集_005.zip`。
- 不满 14 个就留在原地，等下次继续凑。
- 记录会保存在 `_portfolio_move_logs`；生成过程中先写入隐藏临时目录，全部成功后再转正，失败不会留下半个作品包。
- 如果触发整理和压缩，会按节点连续提示：`已创建作品包`、`已整理作品集`、`已生成ZIP压缩包`。

这个整理已经融入 `一键生成作品包.vbs`，平时不用再额外点分组脚本。旧的手动分组脚本可以作为补救工具保留。

## 重要规则

- 一条文案对应一篇笔记。
- 没复制文案时，会在屏幕中间显示白绿色圆角小提示“请先复制文案”，不会移动图片。
- 已经复制文案、但这一层没有作品图时，会提示“请先下载作品图”，不会生成空作品包，也不会清空剪贴板。
- 查重以整组图片的精确 SHA-256 集合为主。图片数量相同、每张图片哈希组成的集合完全相同，就直接判定重复；即使文案略有变化也不会再创建作品包。本次图片进入 Windows 回收站，剪贴板文案被清空，并提示“本次为重复下载，已删除本地图片和文案。”
- 文案也会计算规范化后的整篇 SHA-256。文案相同但图片不同，说明是重新生成的作品：工具会继续创建作品包，并提示“本组有历史相似文案，但图片不同，已继续创建作品包。”
- 图片不是字节级重复、但画面结构与某个历史包高度近似时，工具会停止本次打包、保留下载图片，提示相似历史包，并把该文件夹路径复制到剪贴板。确认确实是新作品后，重新复制文案并再次运行，工具会对同一组图片单次放行。
- 视觉近似使用 64 位 dHash 感知哈希，默认要求每张图都能一一匹配、单图汉明距离不超过 6、整组平均距离不超过 3。它只负责预警，不会自动删除近似图片。
- 查重历史保存在成品库 `_作品历史数据\作品历史数据库.json`，另有同目录备份和程序目录隐藏镜像 `.workpkg_history_backup.json`。旧作品包即使被删除，历史记录仍然保留。
- 成功后会清空剪贴板，减少误用上一条文案的概率。
- 如果生成过程中失败，工具会把已移动到暂存目录的原图恢复到原位置，再删除未完成的暂存目录。
- 调试或首次使用时，可在 PowerShell 运行 `make_work_package.ps1 -Preview`，只查看计划，不移动文件。

## 历史数据库与已有作品查重

- 主数据库：`<成品库>\_作品历史数据\作品历史数据库.json`
- 上一版备份：`<成品库>\_作品历史数据\作品历史数据库.backup.json`
- 独立恢复镜像：程序目录隐藏文件 `.workpkg_history_backup.json`

数据库只保存文案哈希、图片精确哈希、感知哈希、作品包名称和路径，不保存文案正文或图片副本。删除旧作品包不会自动删除历史记录。

只查看现有作品的重复情况：

```powershell
.\make_work_package.ps1 -RebuildHistory -Preview
```

重建数据库，并把后出现的精确重复作品包送入 Windows 回收站：

```powershell
.\make_work_package.ps1 -RebuildHistory -CleanExistingDuplicates
```

同一图片组按文案文件修改时间保留最早作品。清理前建议先运行预览命令确认数量和路径。

## 修改成品库位置或名字

打开 `workpkg_config.json`，修改：

```json
{
  "library_name": "成品库",
  "library_path": ""
}
```

比如可以改成：

```json
{
  "library_name": "团建成品库",
  "library_path": "D:\\Projects\\MyProject\\团建成品库",
  "visual_similarity_enabled": true,
  "visual_similarity_max_distance": 6,
  "visual_similarity_max_average": 3
}
```

- `library_path` 是绝对路径，设置后优先使用它。
- 不需要视觉近似预警时，将 `visual_similarity_enabled` 改为 `false`；两个阈值越小越严格，不建议随意调大。
- `image_inbox_path` 是浏览器实际保存图片的位置；`library_path` 是成品库位置。
- 重新运行安装器升级时，会保留已有配置；只有明确传入的新参数才会覆盖对应设置。
- 不想编辑配置文件时，直接双击 `设置作品包目录.vbs`；分别粘贴图片下载目录和成品库后点击“保存”即可。油猴脚本菜单里的“设置本地作品助手（下载目录+成品库）”调用的是同一个入口。
